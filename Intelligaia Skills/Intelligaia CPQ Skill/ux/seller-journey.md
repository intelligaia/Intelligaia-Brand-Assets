# Seller Experience — Journey & Task Flow

## 1. Enter from Selling Context
Preferred experience:
customer/deal context → seller intent → existing transaction check → start/resume correct quote/lifecycle work.

Avoid creating a new quote merely because the seller cannot find the current one.

## 2. Start vs Resume
Before creation, determine:
existing active quote? → current version? → ownership/access? → lifecycle transaction already pending? → resume or create.

## 3. Quote Creation
Reuse authoritative context such as customer, opportunity, partner, currency and relevant commercial attributes where supported.

Make defaulted/inherited values understandable when they affect selling decisions.

## 4. Product Discovery
Support the seller in finding eligible products/solutions using business language, search/filter and relevant recommendations where evidence supports them.

## 5. Configure
Guide required choices and dependencies. Show invalid/incomplete state early enough to avoid wasted pricing/approval work.

## 6. Price
Calculate using authoritative pricing rules. Seller UX should clearly show when pricing is pending, stale, recalculated or blocked.

## 7. Discount
Seller enters/adjusts permitted commercial request → sees net impact → sees approval consequence → provides rationale where required.

## 8. Validate
Before approval/customer presentation, surface unresolved:
configuration → pricing → commercial → date/term → required-data → policy issues.

## 9. Approval
Seller should know:
why approval is required → which version is submitted → current approval stage/status → what changes would invalidate it.

## 10. Customer Presentation
Generate/present the approved/allowed commercial version. Preserve linkage between customer-facing artifact and source quote/version.

## 11. Revision
Customer change → create/revise governed version → identify material delta → recalculate/revalidate → reapprove if required.

## 12. Acceptance
Capture or correlate the accepted commercial version according to the business process.

## 13. Order / Downstream Handoff
Seller should see whether the accepted transaction is:
ready → submitted → processing → completed → partially completed → blocked.

## 14. Follow-Up
Provide business-relevant downstream references/status without requiring the seller to inspect integration logs.

## 15. Amendment Entry
Customer asks for change → identify authoritative installed/subscription state → choose change intent → construct delta.

## 16. Renewal Entry
Identify renewal work → source current term/subscription → account for pending changes → construct next-term commercial proposal.

## 17. Cancellation / Non-Renewal
Where seller-owned, distinguish immediate/future cancellation and end-of-term non-renewal.

## 18. Handoff to Other Roles
Seller may hand work to:
deal desk; approver; operations; partner; finance/billing; customer success.

The transaction should retain context and ownership.

## 19. Interrupt / Resume
If seller leaves mid-flow:
save governed draft → show pending tasks → resume correct version/state → explain changes made by others.

## 20. Completion
Completion should reflect the business goal, not merely “record saved.”

## Diagnostic Questions
- Where does the seller leave their primary selling context?
- What information must be re-entered?
- Where can duplicate quotes be created?
- Which validations happen too late?
- Which statuses require manual follow-up?
- Where is version/approval state unclear?
- Which lifecycle tasks start from reconstructed rather than authoritative state?

## Guardrail
Specific screens, systems, automation, timings and observed pain points require evidence.
