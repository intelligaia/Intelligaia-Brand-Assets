# CPQ Usability Issues

## Purpose
Provide an evidence-safe framework for identifying, classifying, analyzing, and prioritizing usability problems across CPQ/Q2C experiences.

This module does not assume that a usability issue exists. Current-state findings must come from research, observation, analytics, support evidence, or supplied project artifacts.

## Issue Definition
A useful finding should connect:
**User / Role → Goal → Context → Observed Behavior → Friction → Consequence → Evidence → Root-Cause Hypothesis → Dependency → Opportunity**

Avoid vague findings such as “the UI is confusing.”

## Evidence Labels
Use explicit labels:
- **Validated** — directly supported by current evidence.
- **Historical** — supported by older evidence; current validity requires confirmation.
- **Hypothesis** — plausible explanation not yet validated.
- **Proposed** — future-state design/change.
- **Unknown / Validation Needed** — insufficient evidence.

## Guardrail
Do not invent user complaints, task times, click counts, error rates, severity, frequency, revenue impact, adoption problems, or platform limitations.
