# CPQ Impact Record Template

## Identification
**Impact ID:**  
**Change / Requirement:**  
**Evidence Status:** Validated / Historical / Hypothesis / Unknown  
**Assessment Status:** Draft / Validating / Approved / Superseded  

## Change Description
What is changing and why?

## Current Baseline
What current behavior/state is evidenced?

## Scope
Role → transaction → product → region/channel → system → lifecycle stage.

## Direct Impact
What changes immediately?

## Upstream Impact
What new/changed inputs, rules, data, decisions or user behavior are required?

## Downstream Impact
What consuming processes/systems/states may change?

## Commercial Impact
Configuration → price → discount → approval → quote/version → order.

## Lifecycle Impact
Baseline → pending state → amendment → renewal → cancellation → effective date → billing/service.

## Data Impact
Meaning → authority → mapping → history → migration/backfill → reporting.

## Integration Impact
Contract → state/status → compatibility → errors → retry/idempotency → reconciliation.

## Security Impact
Authorization → confidentiality → partner/customer separation → audit.

## User Impact
Role → task → comprehension → effort → recovery → accessibility.

## Operational Impact
Monitoring → support → exception → reconciliation → training/runbook.

## Risks
Positive / Negative / Unintended / Integrity / Transition.

## Dependencies
Reference dependency IDs or domains.

## Assumptions / Unknowns
Explicitly list unresolved points.

## Mitigation
What reduces material negative impact/risk?

## Validation
What discovery, testing, research or evidence is required?

## Acceptance / Regression
Which scenarios and criteria prove safe implementation?

## Measurement
Success and guardrail evidence; no invented baseline/target.

## Traceability
**Change → Impact → Dependency → Risk → Mitigation → Acceptance → Measurement**

## Guardrail
Predicted impact must remain labeled as hypothesis/estimate until validated.
