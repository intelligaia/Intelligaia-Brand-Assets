# Gap Prioritization & Closure

## 1. Prioritization Inputs
Consider:
requirement criticality → evidence strength → user consequence → business consequence → integrity/control risk → reach → strategic alignment → dependency → implementation uncertainty.

## 2. Required vs Desired
A regulatory/control/business-critical requirement may outrank a high-friction convenience issue.

## 3. Evidence Strength
Do not give a poorly evidenced gap false priority through confident language.

## 4. Risk-Critical Gaps
Give explicit attention to gaps that can create:
wrong customer; wrong product; wrong price; approval bypass; wrong version; duplicate order; incorrect lifecycle state; billing/service mismatch; unauthorized data exposure.

## 5. Reach
Use measured scope/volume where available.

Otherwise record qualitative scope and unknown frequency.

## 6. Dependency
A lower-visible foundational gap may unlock multiple journey improvements.

## 7. Feasibility
Do not label “quick win” without validating platform, integration, data, policy and operational dependencies.

## 8. Closure Options
A gap may be:
fixed → mitigated → accepted → deferred → transferred to process/control → invalidated by new evidence → no longer applicable.

## 9. Closure Evidence
A gap is not closed merely because a feature was delivered.

Verify the required outcome and acceptance/success evidence.

## 10. Residual Risk
If mitigation leaves known limitations, record residual risk and ownership.

## 11. Roadmap
Sequence:
enabling decisions/data/integration → dependent capability → UX/process → rollout/operations → measurement.

## 12. Prioritization Record
Recommended fields:
gap ID → requirement/outcome → evidence → consequence → risk → reach → dependencies → priority rationale → closure approach → validation → owner/decision.

## 13. Quantitative Scoring
Use only a project-approved model. Keep underlying evidence visible.

## 14. Benefit
Separate:
validated benefit → modeled estimate → hypothesis.

## 15. Reassessment
Revisit priority when:
new evidence → requirement changes → platform changes → dependency resolved → risk changes → scope changes.

## Output
**Priority Rationale → Dependencies → Closure Strategy → Validation → Residual Risk → Success Evidence**

## Guardrail
Never fabricate ROI, effort, reach, severity, frequency or scoring inputs.
