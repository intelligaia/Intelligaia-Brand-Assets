# User, Operational & Rollout Impact Analysis

## 1. Role Impact
Assess separately:
seller → partner → approver → deal desk → operations → billing/finance → customer success → admin/support.

Not every role is impacted.

## 2. Task Impact
For each affected role:
entry → action → decision → handoff → exception → completion.

## 3. Cognitive Impact
Could the change improve or worsen:
orientation → comprehension → decision confidence → error understanding → lifecycle clarity?

Validate with research where material.

## 4. Access Impact
Will roles gain/lose:
visibility → edit → discount → approval → ordering → lifecycle action → commercial/billing data?

## 5. Process Impact
Does the change:
add/remove step → shift ownership → create handoff → alter approval → change exception path?

## 6. Operational Support
Assess need for:
monitoring → queue → reconciliation → manual correction → escalation → runbook → support training.

## 7. Exception Volume
Do not predict ticket/error volume without evidence/model.

## 8. Training
Potential needs:
new terminology → workflow → role responsibility → commercial interpretation → error recovery.

## 9. Documentation
Update affected:
user guidance → process docs → support/runbooks → data dictionary → integration contract → training.

## 10. Rollout
Consider:
pilot → phased role/region/product rollout → feature/configuration control → coordinated platform release.

Do not assume a rollout pattern.

## 11. Transition State
How are in-flight:
quotes → approvals → orders → amendments → renewals handled during change?

## 12. Backward Compatibility
Can old and new transaction states coexist safely?

## 13. Support Readiness
Before launch ensure relevant support roles can identify:
transaction → version → status → error → owner → recovery.

## 14. Measurement
Define success/guardrail evidence:
completion → error/rework → support → cycle time → comprehension → downstream correctness.

No invented baseline/target.

## 15. Adoption
Adoption is not simply login/use. Define the intended behavior/outcome.

## 16. Rollback
For high-risk changes identify whether and how the business can safely revert, especially after data/state changes.

## 17. Communication
Communicate:
what changes → who is affected → effective date → required action → support path.

## 18. Post-Launch
Validate:
expected outcome → unexpected impact → exception patterns → data/reconciliation → user feedback.

## Output
**Roles → Tasks → Process → Access → Operations → Training → Transition → Rollout → Measurement → Post-Launch**

## Guardrail
Do not invent adoption, training effort, support load or rollout dates.
