# UX & User Research Opportunities

## Use When
Evidence indicates seller, partner, approver, operations or customer friction that requires behavioral validation or interaction redesign.

## Typical Evidence Signals
- repeated navigation/context switching;
- difficulty understanding quote/configuration state;
- unclear errors or recovery;
- high cognitive load in configuration/cart;
- approval status uncertainty;
- partner/customer role confusion;
- manual comparison of versions;
- lifecycle actions with unclear consequences;
- user stories that prescribe UI without validated need.

## Service Motions
### Contextual Research
Interviews, workflow observation and task analysis to validate actual behavior and pain.

### Journey / Service Blueprinting
Connect user actions with backstage systems, decisions, handoffs and failure states.

### CPQ Interaction Redesign
Improve configuration, cart, quote, discount, approval, lifecycle and recovery experiences.

### Prototype & Usability Validation
Test proposed workflows before implementation.

### Design System / Experience Consistency
Standardize repeated patterns where fragmented UI behavior is evidenced.

## Expected Outcomes
Validated user needs, clearer task flows, reduced interaction ambiguity, testable prototypes and experience requirements linked to business/process constraints.

## Validation
Task success → error/recovery comprehension → usability findings → adoption behavior → user-reported effort, where measured.

## Guardrail
Do not infer poor UX solely because a process has many steps. Complexity may be commercially necessary.
