# Advisory & Assessment Opportunities

## Use When
The problem, current state, ownership, evidence, requirements or target architecture is unclear enough that implementation would be premature.

## Typical Evidence Signals
- inconsistent descriptions of current process;
- unclear system/source-of-truth ownership;
- conflicting stakeholder requirements;
- manual workarounds with unknown root cause;
- fragmented quote-to-order/lifecycle flow;
- uncertain platform capability/configuration;
- large backlog without prioritization;
- integration failures without end-to-end state model.

## Service Motions
### CPQ/Q2C Current-State Assessment
Map actors, process, systems, states, rules, data, handoffs, exceptions and pain evidence.

### Capability & Gap Assessment
Compare required business outcomes with evidenced current capability.

### Quote-to-Cash Journey Assessment
Trace new business, amendment, renewal, cancellation and channel flows end to end.

### Platform / Architecture Assessment
Clarify platform responsibilities, source-of-truth, integration boundaries, lifecycle authority and modernization options.

### Requirements & Backlog Rationalization
Normalize source requirements, remove duplication, expose dependencies, prioritize discovery and create acceptance-ready stories.

## Deliverables
Evidence inventory → current-state map → findings → gaps/risks → prioritized recommendations → future-state principles → roadmap/discovery backlog.

## Expected Outcomes
Better decision quality, clearer scope, reduced implementation ambiguity, traceable requirements and a defensible modernization plan.

## Guardrail
Recommend assessment when evidence is insufficient; do not use uncertainty as proof that a platform must be replaced.
