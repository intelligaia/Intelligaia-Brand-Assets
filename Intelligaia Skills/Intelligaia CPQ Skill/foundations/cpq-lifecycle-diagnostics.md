# CPQ Lifecycle Diagnostics

## Purpose
Provide reusable questions for assessing a CPQ/Q2C environment without bloating the lifecycle reference.

# Process
- Where does the seller start?
- How many tools are required?
- Which steps are manual?
- Where does work wait?
- Where does rework occur?
- Which exceptions dominate cycle time?

# Product / Configuration
- How is the catalog structured?
- Who owns product rules?
- What makes a configuration valid?
- How are bundles/options/attributes governed?
- Where does Deal Desk intervene?

# Pricing
- What is the price source?
- Which pricing dimensions exist?
- Which discounts are automatic vs discretionary?
- Can users explain the final price?
- What changes trigger recalculation or approval?

# Quote
- How are quotes created and revised?
- Can multiple scenarios exist?
- Which quote is authoritative?
- How are proposals generated?
- How is customer-requested change handled?

# Approval
- What triggers approval?
- Is the approval matrix explicit?
- Sequential, parallel or group?
- What happens after rejection or need-more-information?
- How is reapproval determined?
- Are SLA/status/delegation visible?

# Contract
- When is Legal involved?
- What is standard vs non-standard?
- What changes force quote revision/reapproval?
- How are redlines and signatures handled?

# Order
- What downstream data is mandatory?
- What is re-entered?
- How is quote/order fidelity validated?
- What causes manual order touch?
- What happens when downstream validation fails?

# Billing
- How does commercial data reach billing?
- What causes reconciliation?
- How are subscriptions established?
- How are amendments/renewals synchronized?

# Amendment / Renewal
- How are active subscriptions/assets located?
- Are renewal opportunities/quotes automated?
- Can sellers see purchase and pricing history?
- How are co-term, add-ons, upgrades and partial renewals handled?
- How are effective dates/proration controlled?

# Data / Integration
- What is the system of record for each entity?
- Which IDs link systems?
- What triggers each handoff?
- Where do synchronization errors occur?
- How are retries and reconciliation handled?
- Who owns monitoring and correction?

# UX / Adoption
- Where must users remember rather than recognize?
- Is status visible?
- Are errors caught early?
- Which standard tasks require expert support?
- Where does context switching occur?
- What creates training/support burden?

# Evidence
For every material finding capture source, date/context, confidence and whether it is Confirmed, Inferred, Unknown or Historical.
