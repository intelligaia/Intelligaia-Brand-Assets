Landing pages.

A complete guide to producing an Intelligaia-quality landing page — hero, sections, footer — for intelligaia.com, product launches, or campaign microsites.

Overview

What defines an Intelligaia landing page.

Every landing page in the Intelligaia system uses the yellow-banner hero pattern, a single primary CTA, and one hero illustration from the approved library. Below the fold, sections follow a fixed rhythm: promise · proof · offer.

Signature

Yellow banner hero

Full-bleed #FFC800, no gradient. Content on the left, illustration on the right.

Rhythm

Hero → Promise → Proof → Offer

Four sections. Each earns a full viewport moment. Lenis smooth scroll.

CTA

One primary. One ghost.

Never two primary buttons in the same viewport. Ghost = secondary path.

Illustration

One hero, from the library

Isometric-gradient or 3D-render banner from assets/marketing/banners/.

For agents

Prompt an agent can run.

Copy the prompt below, replace bracketed inputs, and hand to an agent with access to this system. The JSON spec at the bottom of this page is the authoritative source.

Agent prompt
Produce an Intelligaia landing page for [OFFER / PRODUCT / SERVICE].

Follow the Landing Pages playbook at:
  Dark - Intelligaia Playbook - Landing Page Hero.html

Inputs required:
  - headline        (max 8 words, outcome-focused)
  - sub_copy        (one sentence, max 24 words)
  - primary_cta     (verb + noun, max 3 words) + href
  - secondary_cta   (optional, ghost style)
  - hero_asset      (path from assets/marketing/banners/ or assets/marketing/people/)
  - promise_paragraph + 3 pillars
  - proof_items     (2–4 case studies or logos)
  - offer_block     (what/how/who)

Constraints:
  - Yellow banner hero (#FFC800), no gradient
  - Oswald 700 headline · Geist 400 body · Geist 500 CTAs
  - One primary CTA per viewport
  - max-width 1440px inner container, 48px gutter
  - Sections in canonical order: hero → promise → proof → offer → final CTA
  - Must pass all guardrails in the JSON spec below

Output: single self-contained HTML file. Include the JSON spec block for downstream parsing.

Inputs the agent needs

Guardrails

✓One primary CTA per viewport. Ghost buttons are fine as secondary.
✓Yellow #FFC800 hero. Flat colour, no gradients.
✓Hero illustration always from the approved/ library — never AI-generated on the fly.
✓All body copy ≤ 24 words per sentence. Break longer thoughts.
✕No pixel fonts (Silkscreen). No two H1s on the page.
✕No stock photography. No gradients on the yellow banner.
✕No autoplay video in the hero. Never.
