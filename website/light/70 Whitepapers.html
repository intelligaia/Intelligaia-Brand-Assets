Deconstructed

How the document is put together.

Sticky rail220px. Ten numbered sections, active state follows scroll.
Measure1080px content inside a 1480px frame. Long-form reading width.
Type pairingTrirong serif headings against Raleway sans body.
PaperWarm #FAFAF6 rather than white. Reduces glare over long reads.
Section shapeClaim heading, then design track and engineering track together.
CloseImpact section, then a genuine limitations section. That is what earns trust.

Prompt
Produce an Intelligaia engineering whitepaper for [PRODUCT].

Reference: examples/Whitepaper — D3 AI Assistant.html
Playbook: 70 Whitepapers.html

Match the reference layout:
  Trirong serif, Raleway sans, warm paper #FAFAF6
  1480px frame, 1080px measure, 220px sticky rail

Sections:
  01 Project context      06 AI design principles
  02 Root issues          07 Information architecture
  03 The proposal         08 Proposed workflows
  04 Research approach    09 Executive archetypes
  05 Discovery flow       10 Impact

Inputs:
  design_track   user model, interface behaviour, hierarchy, accessibility
  eng_track      architecture, data flow, latency, cost, integrations
  results        measured outcomes
  limitations    real, specific, unflattering

Output: single self-contained HTML file plus the JSON spec block.

Must

  • Every section covers design and engineering before advancing
  • One architecture diagram from the Diagrams playbook
  • Latency and cost in real units with test conditions
  • A genuine limitations section

Never

  • Marketing language in a technical document
  • Architecture diagrams without annotation
  • Benchmarks without stated conditions
  • Novelty claims without comparison
